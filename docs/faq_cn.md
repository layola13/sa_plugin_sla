# SLA FAQ

> 本文为英文原版 [SLA FAQ](./faq.md) 的中文对照版。

> 快照：2026-06-22。本 FAQ 描述当前的 `sa_plugin_sla` 实现及其预期方向。当源码与较早的设计说明不一致时，以当前编译器实现为准。

## A. 语言定位与设计目标

**1. SLA 的核心设计目标是什么？它应该在哪些方面胜过 Rust / C / Zig / Go？**

SLA 是 SA 的静态类型前端。它的主要目标是让 SA 的所有权、清理、分支合并和底层安全规则能够从更高级的语言中使用。它应在编译器管理的清理安全性上胜过 C/Zig，在易用性上胜过原生 SA，并且对于不需要 Rust 完整生命周期机制的数据导向系统而言，比 Rust 更简单。

**2. SLA 最重视哪些价值？**

优先级顺序是：简单的语义、可预测的 SA 降级、显式的数据布局、静态类型检查、编译器管理的清理，以及实用的系统/ECS 易用性。它并不打算像动态脚本语言那样隐藏所有成本。

**3. SLA 是系统语言、数据导向语言、引擎语言还是通用语言？**

SLA 应保持为通用的 SA 前端，并强烈偏向数据导向和系统编程。它不得把 ECS 或游戏引擎关键字硬编码到编译器中。

**4. 用户应该有什么样的心智模型？**

可以把它理解为「类 Rust 语法 + Zig/C 式的直接性 + 底层 SA 所有权」。变量简单，控制流直接，但编译器仍会跟踪资源并发出释放指令。

**5. 有什么非主流的设计点值得保留？**

SLA 保持变量默认可变，并倾向于显式的数据移动，而不是庞大的借用检查器词汇表。这是有意为之，但编译器仍需要强大的资源跟踪。

## B. 变量、赋值与值语义

**6. 默认可变是指重新绑定、字段修改，还是两者都有？**

对于 `let`，它意味着本地绑定可以被再次赋值，并且在值可用时可以更新所拥有的聚合体字段/元素。`const` 是不可变绑定形式。

**7. 在 `let x = ...` 之后 `x = ...` 总是合法的吗？**

当 `x` 是可变局部变量且右侧类型匹配时是合法的。对于 `const`、不存在的绑定，或者所有权状态已被消费的值，则不合法。

**8. 函数参数默认是按值传递吗？**

是的。写成 `x: T` 的参数是拥有权/值参数。借用参数用 `&` 书写，例如 `x: &T`。

**9. 按值传递后，调用方的值还能用吗？**

对于标量/类似复制的值，可以。对于拥有的堆/资源值，除非 API 明确是借用，否则按值传递应视为所有权转移。对于必须保持可用的状态，请使用返回值或 `&T` API。

**10. SLA 有移动语义吗？**

有。编译器对拥有值和清理进行建模，`^expr` 是语言层面的显式移动操作符。

**11. 像 `Entity` 这样的小结构体有自动复制语义吗？**

标量字段和字段读取是类似复制的。小型纯数据结构可以通过 `@derive(copy)` 选择加入，这会让 `let b = a;` 以及普通的按值调用生成独立的逐字段复制，而不是转移原绑定。

**12. `let b = a;` 是什么意思？**

这取决于类型。原始值会被复制。拥有的资源/容器值应视为已移动/所有权已转移，除非具体类型或 API 提供了 clone/copy 行为。

**13. 内置标量是复制值吗？**

是的：整数、浮点数和布尔值都是类似复制的值。

**14. 读取结构体字段后，原对象还能使用吗？**

对于普通的字段读取，可以。现有测试（例如结构体字段复制不会移动所有者）已覆盖这一点。

**15. 在 `world.entities = allocator;` 中，`world` 是本地副本还是调用方状态？**

如果 `world` 是以 `world: World` 传入的，那么它是函数本地的拥有值。要更新调用方，请返回更新后的 world，或使用基于借用的 API。

**16. SLA 是否区分绑定可变性与对象内容可变性？**

部分区分。`const` 保护重新绑定。对象/内容的修改主要由所有权/借用状态和类型的 API 控制，而不是像 Rust 那样区分 `mut`。

**17. 是否支持 `a, b = b, a` 这样的多重赋值？**

没有文档记录稳定的语言级多重赋值。请使用临时变量。

**18. 是否支持 `{x, y} = point` 这样的字段解构赋值？**

存在元组解构。结构体模式解构还不是一个成熟的通用特性。

**18a. SLA 在绑定和解构中是否支持空白标识符 `_`？**

支持。`_` 被视为丢弃接收器：它不引入符号，并且如果被丢弃的值带有所有权，编译器会将其降级为立即清理/销毁路径。

**18b. SLA 是否支持 `using` 静态扩展？**

支持。`using module_path;` 在当前作用域内为来自该模块的公有函数启用方法式调用。编译器首先解析直接字段和本地函数，然后查询激活的 `using` 集合。歧义匹配会被报告为硬错误，而不是在运行时猜测。

**18c. SLA 是否支持带 `&` 风格结构体展平的 `type` 别名？**

支持，作为仅前端的、用于平坦数据布局的别名表面。像 `type BulletData = Transform & Velocity & { damage: i32 };` 这样的声明会在前端展开为展平的字段布局，使结果值表现得像一个单独的普通结构体。该别名只为编译期可读性而存在；它不引入运行时包装层。

**18d. SLA 是否支持用于操作符的受限 `@overload` 块？**

支持。对显式目标类型的 `+`、`-`、`*`、`/`，支持 `@overload Type { fn +(self: Type, other: Type) -> Type { ... } }`。前端在类型检查期间把操作符降级为静态函数调用，因此没有运行时分发开销。如果没有重载匹配，编译器回退到现有的内置数值操作符规则。裸 `overload` 不是合法的声明形式。

**19. 是否有 `const`、`final` 或 `readonly`？**

`const` 存在于顶层和本地不可变绑定。`final` 和 `readonly` 不是当前的语言关键字。

**20. 编译器是否会把值入/值出更新优化为就地修改？**

不要把它当作语义保证。编译器和 SA 后端可能会优化，但 API 应直接表达所有权或借用。

## C. 基本类型与字面量

**21. 有哪些数值类型？是否有 `usize/isize`？**

当前原始类型包括 `i8/i16/i32/i64/isize`、`u8/u16/u32/u64/usize`、`f32/f64`，以及别名 `int` -> `i64` 和 `float` -> `f64`。

**22. 数值转换是显式的吗？**

使用显式 `as` 转换。不要依赖隐式截断或提升。

**23. `bool` 只有 `true` / `false` 吗？**

在 SLA 层面是的。它在内部降级为 SA 的整数表示。

**24. 有字符串类型吗？是 UTF-8 吗？**

通过 SA 标准库提供了字符串设施（`String`、`str`/切片风格 API）。字符串字面量以 UTF-8 常量发出。

**25. 字符串字面量是什么类型？**

取决于上下文：对于受支持的标准库调用，编译器可以把它降级为拥有的/字符串表示或借用字符串表示。请把它当作 UTF-8 文本，而不是通用的以 null 结尾的 C 字符串。

**26. 有 `char` 吗？**

当前 SLA AST 中没有一等 `char` 原始类型。`sa_std` 中可能存在字符辅助函数，但那是库表面，不是核心语法。

**27. 有 `null`、`nil` 或 `none` 吗？**

没有通用的 null/nil 值。使用 `Option<T>`/`None` 表示缺失。裸指针属于底层设施，不应成为普通的应用程序空值处理方式。

**28. 支持元组吗？**

支持。元组类型和元组解构都受支持。

**28a. 支持切片 rest 模式和结构体更新语法吗？**

支持。`[a, b, ..rest]` 切片解构和 `Struct { field: expr, ..base }` 结构体更新都受支持，并直接在前端降级。

**28b. `using` 与数据导向风格兼容吗？**

兼容。它是一个显式选择加入的层，用于在普通模块函数之上提供易用的方法式调用，因此保持调用图是静态的，并保留仅前端降级的模型。

**28c. SLA 支持 `<=>` 三路比较吗？**

支持。`<=>` 返回来自 `sla_std/cmp.sla` 的 SLA 标准库 `Ordering` 外观（facade），而不是一个新的编译器自有的枚举。当用户代码需要 `Ordering::less()`、`ordering.is_lt()` 或 `ordering_value(ordering)` 等方法时，请导入 `sla_std/cmp.sla`。编译器只解析/类型检查该操作符，并把它降级为已有的 `sa_std/cmp.sa` 序值 `-1`、`0` 和 `1`。

**29. 数组和 `Vec` 是分开的吗？**

是的。固定数组是类似值的固定大小聚合体。`Vec<T>` 是动态标准库容器。

**30. 支持固定数组 `[T; N]` 吗？**

支持，支持定长数组类型和数组字面量。

## D. 结构体、枚举、联合与 ADT

**31. 结构体是纯数据吗？有字段隐私吗？**

结构体主要是数据布局。公有/私有支持仍然比较粗糙；不要把 Rust 风格的逐字段隐私当作稳定特性来依赖。

**32. SLA 有枚举吗？是 C 风格还是 Rust 风格 ADT？**

SLA 有 `enum`，其变体可以携带载荷，并支持模式匹配。它更接近 Rust ADT，而不是普通的 C 枚举。

**33. `match` 会解构枚举吗？**

会。`match`、`if let`、`while let` 和 `let ... else` 支持常见形式的枚举模式，包括 `Some`、`None`、`Ok` 和 `Err`。

**34. 有 `union` 或带标签联合吗？**

解析器接受 `union` 语法，但健壮的、面向用户的模型应被认为不如 `struct` 和 `enum` 成熟。

**35. 结构体字段有默认值吗？**

没有通用的默认字段语法。请使用构造函数/辅助函数。

**36. 支持匿名结构体或元组结构体吗？**

没有文档记录稳定的匿名结构体或元组结构体表面。

**37. 支持递归类型吗？**

请使用间接方式，例如 `Box<T>`、`Rc<T>`、`Arc<T>`、裸指针或容器句柄。直接无限大小的递归结构体是无效的。

**38. 支持 `eq/hash/copy/debug` 的 derive 吗？**

对于当前的纯数据结构体表面是支持的：`@derive(copy, eq, ord, hash, debug)` 会被编译器按语义展开。`copy` 对派生结构体执行逐字段复制，`eq` 启用 `==`/`!=`，`ord` 启用字典序比较操作符，`hash(value)` 返回一个 `u64`，`debug(value)` 返回一个 `String` 调试渲染。未知的 derive 名称如果不使用其语义，仍会作为中性注解被接受。

**39. 支持操作符重载吗？**

支持，采用受限的前端形式 `@overload Type { fn +(self: Type, other: Type) -> Type { ... } }`。它仅限于 `+ - * /`，并在类型检查期间降级为静态函数调用，因此没有运行时分发开销。裸 `overload` 不是合法的声明形式。

**40. 在没有 derive/copy 的情况下，当前推荐的 `Entity` 写法是什么？**

对于像 `Entity` 这样的小型类值结构体，首选 `@derive(copy, eq, ord, hash, debug)`。不使用 derive 时，请为相等性/哈希/排序使用显式的构造函数和辅助函数。

## E. 函数、方法与调用约定

**41. 函数只能是顶层函数吗？`impl` 支持什么？**

存在顶层函数，也支持 `impl Type { fn ... }` 方法。Trait 实现同样会在 AST 和类型检查器中表示。

**42. 方法在语义上与自由函数不同吗？**

大多不同之处不大。方法通过静态解析/UFCS 风格调用降级；除非使用 dyn trait 路径，否则它们不是经典面向对象的虚方法。

**43. 方法接收者能否区分值/引用/只读？**

接收者可以是值、`&self`，或 `^self` 风格的移动/借用形式。当前没有单独的 `view` 关键字。

**44. 支持函数重载吗？**

不支持通用的按签名重载。请使用不同的名称或泛型。

**45. 支持默认参数、命名参数或可变参数吗？**

没有稳定的默认/命名/可变函数参数特性。

**46. 函数能返回多个值吗？**

可以，通过返回元组。元组返回/解构是语言级特性。

**47. 支持递归吗？有尾调用优化吗？**

当生成的 SA 能通过验证时，允许递归。尾调用优化不是语言保证。

**48. 函数是一等公民吗？**

支持函数指针类型，例如 `fn(i32) -> i32`，并已针对存储/传递/调用函数值进行测试。

**49. `fn(Entity) -> i64` 是函数指针类型还是闭包类型？**

它是函数指针类型。闭包使用闭包字面量语法，并单独处理。

**50. 支持 lambda/闭包吗？它们能捕获吗？**

支持多种内联/标准库模式的闭包字面量，例如 `|x| x + 1`。codegen 路径中存在简单的捕获支持，但逃逸到堆上的闭包仍应视为受限。

**51. 支持 inline 提示、泛型特化或 constexpr 吗？**

泛型特化/单态化是核心。`inline` 会被解析。通用的 `constexpr` 执行模型不属于当前 SLA。

**52. 支持函数可见性吗？**

解析器/编译器表面存在 `pub`、`extern`、ABI 形式和 `@no_mangle`。细粒度的模块可见性仍在演进中。

## F. 控制流

**53. 有哪些控制流构造？**

当前语法包括 `if`、`else`、`while`、`while let`、`for`、区间、`break`、`continue`、`switch`、`match`、`if let`、`let ... else`、`return`、`async`/`await`、`unsafe`，以及内联 `asm!` 支持。

**54. 旧示例中是不是缺少 `break`？**

不是。`break;` 和 `continue;` 已实现。较早的 ECS 示例避免使用它们，是因为当时该功能并不总是可用或可信。

**55. 重新赋值给循环变量是否合法/常见？**

对可变局部变量是合法的。这在底层/数据导向代码中很常见，不过在更清晰时应优先使用 `for` 和 `break`。

**56. 有 `for in` 吗？是基于索引还是迭代器？**

有。`for i in 0..n` 是基于区间/索引的。此外还有面向容器的通用 for-in 协议的工作。

**57. 支持 `0..n` 这样的区间表达式吗？**

在 `for` 循环中支持。

**58. `if` 是语句还是表达式？**

AST 把 `if` 建模为表达式，codegen 可以从分支中生成值。在日常写法中它常被当作语句/块使用。

**59. `match` 是语句还是表达式？**

它被表示为带有块分支的表达式式 AST 节点。在所有表达式上下文都经过充分测试之前，建议优先使用简单的返回/赋值模式。

**60. 有 `switch` 语法吗？**

有。`switch` 用于较简单的字面量/相等分支阶梯；`match` 用于枚举/模式场景。

**61. 有 `defer` 或 `scope(exit)` 吗？**

没有面向用户的 `defer`。清理由编译器通过作用域退出和 SA 释放指令插入来管理。

**62. 支持带标签的 break 吗？**

没有文档记录稳定的带标签 `break outer` 特性。

## G. 容器、索引与迭代

**63. `Vec<T>` 在语义上是什么？**

`Vec<T>` 是来自 SA 标准库表面的动态数组，由堆/运行时存储支撑，并通过由编译器降级的方法/宏暴露。

**64. 对 `Vec<T>` 来说 `let b = a;` 意味着什么？**

除非显式克隆，否则视为所有权转移。不要假定深拷贝或廉价的共享别名。

**65. `values[i]` 返回什么？**

对于读取，它返回从索引槽位加载的值。对于聚合或借用情形，编译器对字段/索引访问有专门路径。

**66. `values[i] = x` 是什么？**

它通过 `Vec`/数组降级把 `x` 写入索引容器槽位。测试覆盖了标量和结构体槽位更新。

**67. `len(values)` 返回什么类型？**

长度 API 返回索引大小的整数值（当前外观中为 `usize`/SA 大小的整数）。与 `i64` 计数器比较时请显式转换。

**68. 有哪些标准容器？**

当前标准库/编译器支持包括 `Vec`、固定数组、`Slice`、`String`/字符串视图、`HashMap`、`HashSet`、`BTreeMap`、`BTreeSet`、`VecDeque`、`Box`、`Rc`、`Arc`、`Cell`、`RefCell`、`Mutex`、`RwLock` 以及原子类型。除非 `LinkedList` 出现在活跃的 `sa_std` 中，否则不要假定它存在。

**69. 支持切片/span/视图类型吗？**

通过 `[T]`/`Slice<T>` 风格的类型以及数组/字符串视图降级，存在切片支持。没有实现单独的 `view` 关键字。

**70. 切片是值还是借用？**

应将其视为非拥有的视图/类似借用的值。使用切片期间请保持所有者存活。

**71. 有标准的迭代协议吗？**

区间 `for` 是稳定的。通用/容器 `for in` 支持存在于测试中，但该协议表面仍不如直接索引或显式容器方法成熟。

**72. 支持生成器或惰性迭代器吗？**

没有通用的生成器特性。针对数组、向量、字符串和标准库模式会降级一些类似迭代器的链，但立即/直接的 API 是更安全的模型。

**73. `remove`、`insert`、`swap` 和 `sort` 是内置还是标准库？**

它们是由库/编译器降级的容器方法，不是核心语言语法。请以当前 `sa_std` 表面为准。

**74. 推荐的 `Vec<Entity>` contains/dedup/sort 写法是什么？**

在 `Entity` 的 derive 完成之前，请使用显式的辅助相等性/排序函数或特定于组件的循环。当元素类型具备所需的标量/键支持时，使用标准库辅助函数。

## H. 内存模型与资源管理

**75. SLA 有 GC 吗？**

SLA 不包含追踪式 GC。它依赖所有权、编译器插入的清理，以及 SA/运行时容器析构器。

**76. 像 `Vec`、`String` 和映射这样的堆对象如何管理？**

它们的存储由标准库/运行时 API 管理。SLA 编译器跟踪值并发出释放/清理，以便 SA 验证能够证明资源没有泄漏。

**77. 有 RAII/drop 吗？**

存在由编译器管理的作用域退出清理，目标与 RAII 类似，但没有稳定的用户自定义 `Drop` trait 表面。

**78. 资源会在作用域退出时自动释放吗？**

编译器的设计目标是在作用域退出、分支、提前返回和循环边界处为活跃的拥有值发出所需的释放指令。

**79. 用户能定义自定义析构函数吗？**

不能作为稳定的语言 `Drop` trait。请使用显式的清理函数或标准库/容器 API；生成的 SA 可能会在内部调用运行时释放钩子。

**80. SLA 如何防止 use-after-free/double-free/悬垂引用？**

编译器跟踪所有权状态，并生成由 SA 校验器检查的 SA。借用值和智能指针有额外的编译器/运行时规则。`unsafe` 和裸指针会削弱这些保证。

## I. 引用、别名与借用

**81. SLA 有引用吗？**

有。`&T` 是借用类型，`&expr` 创建借用表达式。

**82. 能否在不复制整个结构体的情况下借用结构体字段？**

可以，字段借用和嵌套智能指针字段借用路径已实现，并由回归测试覆盖。

**83. 允许多个可写别名吗？**

不应假定可以自由允许。拥有值、借用、类似 RefCell 的运行时检查以及 SA 验证都会约束别名。

**84. 如果存在别名，如何避免竞争/别名错误？**

单线程别名安全通过所有权/借用跟踪以及对内部可变性类型的运行时检查来强制。线程安全依赖显式同步原语，例如 `Mutex`、`RwLock`、原子类型、`Arc` 等。

**85. 未来的 SLA 是否应区分只读 `view` 和可写 `ref`？**

有可能，但并不紧迫。如今 `&T` 才是真正的原语。只有当编译器能强制 `ref/view` 的语义时，添加它们才有意义，而不是把它们做成特定于 ECS 的关键字。

**86. 支持指针吗？**

支持。`*T` 用于指针类型，`unsafe` 用于普通安全表面之外的操作。

**87. 可以手动分配堆内存吗？**

可以通过 `Box<T>` 之类的标准库/运行时类型，以及在暴露的情况下通过更低层的分配 API。在可能的情况下，优先使用 `Box`、`Vec`、`Rc`、`Arc` 或 arena 风格的 API，而不是裸指针。

## J. 错误处理与 Panic 模型

**88. `panic(...)` 做什么？**

它降级为 SA 的 panic 行为。在测试中，除非测试标记为 `@should_panic`，否则它会使当前测试失败；在正常执行中，它会中止当前运行。

**89. 有 `Option` 和 `Result` 吗？**

有。它们通过标准库/编译器降级模式和方法得到支持。

**90. 如果没有 `Option`/`Result`，应该用什么？**

在预期会出现缺失或失败的地方使用 `Option`/`Result`。对被违反的不变量使用 `panic`。避免为新 API 使用占位值。

**91. 支持 `try`/`?` 吗？**

支持后缀 `?`，用于 `Option`/`Result` 风格的传播。

**92. 支持异常吗？**

没有通用的异常机制。针对标准库模式存在一些有限的 panic 捕获路径，但异常不是常规的错误模型。

**93. `panic(9400)` 是官方风格还是个人风格？**

数字 panic 码在当前测试中很常见，因为它们紧凑且易于识别。面向生产的代码在可用时应优先使用更清晰的错误值或带消息的 panic 路径。

**94. 是否内置 `assert_eq`、`assert_ne` 或 `assert_panics`？**

存在 `@test` 和 `@should_panic`。完善的 SLA 断言辅助表面仍然是一个优先缺口；许多当前测试使用 `if !cond { panic(code); }`。

## K. 泛型、约束与接口

**95. SLA 支持泛型吗？**

支持。泛型结构体、枚举、函数和 impl 都受支持，并会单态化。

**96. 支持 trait/接口吗？**

支持，`trait` 和 `impl Trait for Type` 会被表示并检查。静态分发是主要模型；dyn trait 支持存在于部分路径中。

**97. 接口约束语法和分发模型是什么？**

当前语法支持 trait 声明、超 trait 和 impl。分发主要是静态/单态化的；在已实现的地方，`dyn Trait` 路径通过运行时胖指针/vtable 支持降级。

**98. 泛型是单态化还是字典传递？**

单态化。具体实例化会生成专用布局/函数。

**99. 支持关联类型、const 泛型或 `where` 子句吗？**

不支持完整的 Rust 风格关联类型、泛型 const 参数或 `where` 子句。固定数组 `[T; N]` 存在，但这与 const 泛型不同。

**100. 如果泛型/trait 不够用，理想的抽象路径是什么？**

让编译器保持语言通用性：改进 derive/codegen 宏、静态 trait 分发、容器标准库和卫生的源码生成。不要把 ECS 或引擎概念硬编码到编译器中。

## L. 编译、SAB、CLI 与工作区构建

**101. SLA 是先编译为 `.sa` 再转换为 SAB 吗？**

从用户可见的流水线来看不是。`sa sla build` 仍然是 `.sa` 文本主线，而 `sa sla sab build`、`sa sla sab workspace`、`sa slab build`、`sa slab workspace` 以及默认的 `sa sla test` 路径会产生 SAB 产物。SAB 路径使用直接的 AST/类型检查器到 SAB 的编码器作为唯一发射路径。当某个特性尚未被该直接编码器覆盖时，编译会以 `UnsupportedSabDirectFeature` 响亮失败；插件绝不会改道走 SA 文本。（此前内存中的 SA 兼容回退已在 2026-09-28 移除，提交 `e96e6b39`；参见 sala 仓库中 SAB 格式白皮书 §4.2，`content/03_sa_asm/08_sab_whitepaper.html`。）

**102. `sa sla sab build` 默认把输出写到哪里？**

默认在 `.sla-cache/sab/` 下写入编译器托管的 SAB 产物。它不会把 SAB 输出放到 `.zig-cache/`，除非明确要求，也不会在源码旁写入同级 `.sab`。

**103. 如何写出一份可见的 `.sab` 文件？**

使用 `sa sla sab build <file.sla> --out <file.sab>` 或 `-o <file.sab>`。工作区构建使用 `--sab-out <file.sab>` 写出额外的检查产物，并使用 `--emit-sab` 写出同级 `.sab`。托管的 `.sla-cache/sab/...` 产物仍会写入，以便后续增量构建复用稳定的输入路径。

**104. SAB 工作区构建如何工作？**

`sa sla sab workspace` 解析当前的 `sa.mod` 工作区，选择默认成员或 `-p/--package`，在 `.sla-cache/sab/` 下写入托管 SAB，然后委托给 `sa build-exe <managed.sab> ...`。SLA 选项之后的额外 `sa build-exe` 选项会被原样传递。

**105. `sa sla init` 和 `sa sla skills` 是做什么的？**

`sa sla init [path]` 会搭建一个最小的 SLA 二进制项目，包含 `sa.mod`、`src/main.sla` 以及包括 `.sla-cache/` 在内的 `.gitignore` 条目。`sa sla skills [--json]` 列出插件能力表面；文本模式还会把 Codex 和 Claude 的 agent skill 文件写入当前目录，风格与 `sa skills` 一致。

**106. SAB 变更是否应该用完整测试套件验证？**

不，默认不应如此。对于测试或 CLI 执行，优先使用聚焦的命令和带 `timeout 120s` 的过滤单元测试。像 `zig build --summary all` 这样的构建命令不需要超时包装。

**107. `sa sla test` 默认使用什么后端？**

`sa sla test` 默认使用 `--test-backend auto`，它会写入托管的 `.sla-cache/sab/...` 产物，并把该 SAB 文件传给 `sa test`。auto 模式使用 SAB 主线：直接的 AST 到 SAB 编码器是唯一的 SAB 发射路径，尚未覆盖的特性会响亮失败而不是回退。它不会回退到 `.test.sa`；使用 `--test-backend sa` 可强制走旧的 `.sa` 文本测试后端。当命令需要明确表明严格的 SAB 意图时，使用 `--test-backend sab`。
